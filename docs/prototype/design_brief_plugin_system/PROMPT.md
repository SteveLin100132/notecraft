# 給 Claude Design 的提示詞 — NoteCraft Plugin System

> 用法：在既有的 NoteCraft design 專案裡開新的 prototype，把下面〈提示詞〉整段貼上，
> 並附上〈素材〉章節列的檔案。建議分兩輪：先跑 A（主畫面），定稿後再跑 B（周邊與狀態）。

---

## A. 主畫面：資料檔檢視頁

```
請為 NoteCraft 設計一個新功能「Plugin System」的 prototype。

NoteCraft 是一套本機執行的個人筆記 Web App（Astro + MDX），既有畫面請沿用 —— 這個功能
不是新產品，是長在既有 app 裡的一塊。設計前先讀：

- BRIEF.md              ← 設計簡報：畫面清單、狀態、硬約束、需要你提案的開放題
- context-ui.md         ← 既有 UI 的實際規格（側邊欄、卡片、版心、token 清單）
- sample-data/er-schema.sample.json ← 真實資料檔的形狀與中文內容
- （我另外附的 ER 圖截圖）← 這張圖是 plugin 渲染出來的內容本體，已經實作完成，
                            你要設計的是包住它的那層外框與導覽，不要重畫這張圖

## 這個功能在解決什麼

目前筆記只能是 md/mdx。Plugin System 讓專案裡的結構化 JSON 資料檔（例：一份資料庫
schema）也能被渲染成一個頁面 —— 渲染器是可安裝的套件，資料是純 JSON。作者在
.notecraft/plugins.json 寫一條映射「planning/schema.json 這個檔交給 er-diagram-renderer
渲染」，網站 build 時就多出一個 /view/planning/schema 頁面。

## 這一輪要設計的畫面

**資料檔檢視頁 `/view/<path>`**（桌機優先，1440 寬）

沿用既有 BaseLayout：左側邊欄不變、右側內容區。這頁的內容區需要：

1. 頁首：標題、一行描述、來源檔路徑（planning/schema.json）、最後更新時間、
   由哪個 plugin 渲染（er-diagram-renderer）。路徑與 plugin 名是這頁獨有的資訊 ——
   它們要能被看見，但不能喧賓奪主壓過標題。
2. 內容區：plugin 渲染出來的東西。這裡用附圖的 ER 圖當佔位內容即可。
   **重點是這塊要能全寬** —— ER 圖是五欄橫向佈局，760px 的筆記版心會把它擠爛，
   所以這頁的版心規則必須與 /notes/<slug> 不同，請明確設計這件事。
3. dev-only 工具列：「以 VS Code 編輯」按鈕（開啟原始 JSON）。正式環境完全隱藏，
   請畫出有 / 無兩種狀態。

## 硬約束

- 只用既有 token（context-ui.md 有完整清單），不新增任何色碼、字級、間距值
- icon 一律 lucide-react，禁用 emoji
- 介面文案全繁體中文（技術名詞如 plugin id、檔案路徑保持原文）
- 不做 RWD 斷點設計，桌機一種寬度即可
- 不要重新設計側邊欄的既有五個項目、不要改筆記頁

## 我要你提案的（BRIEF.md 有完整說明）

- 這頁的版心要怎麼跳脫 760px 又不讓標題區變得空曠
- 「這是資料檔、不是筆記」這件事在視覺上怎麼說
```

## B. 周邊畫面與狀態

```
延續 A 的設計語言，補完 Plugin System 的其餘畫面。一樣先讀 BRIEF.md。

1. **側邊欄新增一區**
   既有五項：總覽 / 筆記 / 系列 / 標籤 / 關於。要加第六項指向資料檔清單。
   請提案這一項叫什麼（中英各一，既有項目都是「總覽 Dashboard」這種雙語形式）
   與用哪個 lucide icon，並畫出展開與收合兩種狀態。

2. **資料檔清單頁**
   側邊欄新那項點進去的頁面。列出專案裡所有被 plugin 渲染的檔。
   每筆要有：標題、描述、原始檔路徑、渲染它的 plugin、更新時間。
   請提案這頁要不要能依 plugin 篩選 —— 一個專案可能同時裝了三四個 plugin。

3. **`/notes` 筆記列表裡的資料檔卡片**
   已定案資料檔也會出現在筆記列表裡（與筆記混排）。既有筆記卡片的結構在
   context-ui.md，請設計一張並排時能一眼分辨、但不破壞列表節奏的資料檔卡片。
   請畫出兩種卡片並排的樣子（列表檢視與格狀檢視都要）。

4. **MDX 內嵌**
   同一份資料也能被嵌在筆記內文裡，用既有的 GeneratedFrame 外框卡片包住
   （那是現有元件，樣式見 note-detail.png）。差別在於這裡的內容來自外部資料檔，
   而非 AI 生成 —— 外框上的標示要不要跟著不同？請提案。

5. **錯誤狀態**
   plugin 的渲染器在瀏覽器裡出錯時，該頁顯示一張錯誤卡片（其他區塊不受影響）。
   內容要有：出錯的 plugin id、資料檔路徑、以及「這不是你的筆記壞了」這個安心感。

一樣：只用既有 token、lucide icon、繁體中文、不新增色碼字級間距。
```

## C. 系列整合（資料檔作為系列的一章）

```
延續 A、B 的設計語言，補上資料檔與「系列」功能的整合。先讀 BRIEF.md §4.7。

背景：NoteCraft 既有「系列」功能 —— 作者把數篇筆記串成有順序的閱讀路徑，
有系列總覽頁（/series）、系列詳情頁（/series/[id]，含整體進度與逐章清單），
筆記頁底部也有系列導覽（章節清單 + 上一篇/下一篇）。

新規則：**資料檔頁也可以是系列裡的一章**，與筆記一視同仁 ——
出現在章節列、計入進度分母、可被標記為「已完成」。
理由是系列表達的是閱讀動線，而一份 schema 的 ER 圖往往正是那條動線上的一站。

要設計的：

1. **系列詳情頁的章節列**
   既有章節列每列有：序號、狀態點、標題、描述、@ai-visualize 標記數徽章。
   資料檔那一列要能被認出來（它沒有標記數，且點下去會跳到 /view/ 而非 /notes/），
   但**不能看起來像是次等的附件** —— 它是正式的一章。請提案怎麼拿捏這個分寸。

2. **筆記頁底部的系列導覽**
   章節清單裡混入資料檔項目、以及「下一篇」剛好是資料檔時的那張卡片。
   既有卡片是為筆記設計的（標題 + 方向箭頭），資料檔要不要有不同的提示？

3. **資料檔頁自己的系列導覽**
   /view/<path> 屬於某個系列時，這頁底部也要有同一組導覽 ——
   請確認它與 A 輪設計的全寬版心不打架（導覽本身應維持一般版心，不需要跟著撐開）。

4. **進度相關的三個顯示位置**
   系列卡的進度條、詳情頁的整體進度、章節列的狀態點。
   資料檔計入分母後這些數字的呈現完全不變，但請確認混合章節時視覺上不會讓人
   誤以為「有兩種進度」。

一樣：只用既有 token、lucide icon、繁體中文、不新增色碼字級間距。
不要重新設計系列總覽頁的系列卡封面（那塊不受影響）。
```

## 一句話版

```
為 NoteCraft 設計 Plugin System 的 prototype：一個把專案裡的 JSON 資料檔渲染成頁面的
機制。讀 BRIEF.md 與 context-ui.md，沿用既有 token 與側邊欄版型，設計四塊 ——
/view/<path> 檢視頁（需要跳脫 760px 版心讓寬元件攤開）、側邊欄新增一區與它的清單頁、
筆記列表裡可一眼分辨的資料檔卡片、以及渲染失敗的錯誤卡片。
只用既有 token、lucide icon、繁體中文，不新增任何色碼字級間距。
```
