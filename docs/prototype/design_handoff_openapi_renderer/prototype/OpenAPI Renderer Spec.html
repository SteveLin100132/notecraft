OpenAPI Renderer

id openapi-renderer對應 **/*.openapi.jsonOAS 3.0 / 3.12026-10-01

長在工作台主區 Body 的 API 文件頁。骨架直接沿用 ER Diagram 的 erx-*：左側導覽樹、Wiki 頁首、欄位表格、Markdown，只新增 OpenAPI 專屬的 method 標記、status、欄位樹與程式碼區。

開啟 Prototype右下 Tweaks 可切換：文件頁 / MDX 內嵌，以及 Petstore、邊界案例、極小、極大四份資料。

四個提案問題

01
範例區放右側欄還是內文流？
放內文流，但在 Request Body 與每個 Response 內把「欄位樹｜範例 JSON」並排，範例欄 sticky。Body 1148px 扣掉導覽 248px 只剩約 900px，Redoc 式第三欄會把說明欄壓到 500px 以下，欄位樹的縮排與 enum 會一直折行。並排只發生在 schema 與它自己的範例之間，對照關係比整頁右欄更直接。視窗低於 1180px 時改為上下排列。cURL / fetch 放在最後一節「範例請求」，頁首另有「複製 path」「複製連結」。
02
長 path 怎麼不爆版？
導覽列：先抽出 tag 內所有 path 的共同前綴，顯示一次在 tag 下方（例如 /v1/organizations/{orgId}），列上只放剩餘部分；仍超過寬度時保留第一段與尾段，中間以 /…/ 取代。完整 path 與 summary 在 hover 卡片上。頁首：path 允許在每個 / 後換行（<wbr>），不截斷；{param} 以橘色底標出，點了會捲到參數表的那一列。
03
巢狀 schema 超過 3 層？
樹最多內縮 3 層。第 3 層的欄位如果還有子欄位，不再出現展開箭頭，改成「深入 N 個欄位」按鈕：把這個節點設為樹的根，上方出現麵包屑（body › items[].options.gift）可逐層返回。$ref 預設收合並可點到 Schema 頁；同一條鏈上第二次出現的 $ref 標成「循環參照」並停止。這樣寬度固定，不會出現第 6 層只剩 200px 的情況。
04
和 ER Diagram 共用什麼？
見下方「共用語彙」。原則是殼與表格一模一樣（同一組 class），只有資料語意不同的元件各自長。

Method 與 status 標記

GETPOSTPUTPATCHDELQUERY 200304404500default
  • 44×18px、10px 等寬粗體，低彩度底配有色字。不靠顏色也分得出：文字本身就是 method 名；形狀再分兩類，唯讀方法（GET / HEAD / OPTIONS / QUERY）是白底外框，會改資料的方法是填色底。
  • status 的圓點在 4xx 變成菱形、5xx 變成方形、default 為空心圓，灰階列印也分得出。
  • deprecated operation：導覽列 path 變淡加刪除線、method 降透明度，右側小字「棄用」；頁面上是灰色外框標籤 + 一行灰底說明，不用警示色。

深連結

目標hash
總覽/view/api/orders（無 hash）
Tag#tag/orders
Operation#op/createOrder（operationId）
沒有 operationId#op/get/pet/{petId}（method + 原始 path）
某個回應#op/createOrder/responses/409：開頁時直接選中該 status
Schema#schema/Order；欄位層級預留 #schema/Order/items[].unitPrice

用 operationId 而非 path，改 path 時連結不會斷；作者沒寫 operationId 才退回 method + path，頁首會提示「未設定」。篩選條件不進 hash，分享出去的連結永遠是乾淨的。

互動

  • / 聚焦篩選（輸入框內不攔截）。篩選同時比對 path、summary、operationId；method chip 可複選；tag 列與區段標題都顯示 命中/總數，沒有命中的 tag 整個隱藏。
  • Esc 逐層退：清除文字 → 清除 method → 收起所有展開的欄位樹與「深入」→ 離開輸入框。每一步在 bar 上閃一個小提示，讓人知道剛剛退了哪一層。
  • 複製（path、連結、範例、schema JSON、cURL）：按鈕本身變成綠色「已複製」1.6 秒，不另跳 toast。
  • 選中的 operation 在導覽中保持在可視範圍；捲動內容時，導覽中的區段（參數 / Request Body / Responses / 範例請求）跟著標示。

規模與資料狀態

情況處理
極小（≤ 4 支、沒有 tag）省略 plugin 導覽，內容置中 880px。總覽直接列出全部 operation 與 schema chip，點進去後 bar 上有「← 總覽」。不放大字或插圖撐場面。
極大（200+、20 tag）超過 6 個 tag 時預設只展開目前所在的 tag；篩選時自動展開所有命中的 tag。總覽有一條依 operation 數等比分段的 tag 長條，一眼看出規模與分塊。
description 全缺虛線框空狀態，寫出該補的欄位：info.description、paths["/pet"].post.description、tags[name="pet"].description、components.schemas.Pet.description。欄位層級缺說明則不顯示說明列。
deprecatedoperation：見上方標記規則。參數與欄位：名稱刪除線 + 灰色「已棄用」，範例產生時略過。
循環 $ref每個節點帶著祖先鏈；同名 schema 第二次出現時停在該列，標「循環參照 · 同上層 X」，沒有展開箭頭。Schema 頁的參照關係也標「自我參照 / 互相參照」。
oneOf / anyOf一個淡藍框，標頭寫「擇一 / 一個或多個」與 discriminator，右側切換選項，框內是該選項的欄位。
allOf攤平成一組欄位，頂端註明合併自哪些 schema，每個欄位小字標來源。
同一 status 多個 content-type回應標頭右側出現 content-type 切換與「N 種格式」；XML、form 仍以 JSON 呈現結構並在範例下方註明。
OAS 3.2 / 2.03.2 以 3.1 規則盡力渲染並警示；2.0（swagger: "2.0"）不渲染，顯示錯誤卡請作者轉檔。

embed 模式

  • 外框沿用工作台既有的資料檔內嵌框：圓角 8px、細框、淺灰 figcaption（橘色「資料檔 · API 文件」膠囊、檔名、「在文件頁開啟」）。上下 22–26px 間距，和前後段落明確分開；筆記內文是 15px 段落，卡片內是 12–13px 介面字，字級落差也幫助區隔。
  • 指定 operation：method + path + summary + 驗證、參數（合併成一張表，加 in 欄）、Request Body 頂層欄位、主要 2xx 回應頂層欄位、其他 status 列成 chip。只展開一層，其餘用「深入」。
  • 不指定：標題、版本、規模數字、method 分布，tag 清單附 operation 數長條。超過 8 個 tag 只列最多的 6 個，其餘一句話帶過。
  • operationId 寫錯：卡片內顯示找不到哪個 id，並指出 options.operation。

試打 API：首版不做

範例區只保留複製 cURL / fetch。理由：

  • 站台是 Netlify 純靜態，請求從讀者瀏覽器直接發出。大多數 API 不會對 *.netlify.app 開 CORS，實際體驗會是「十次有八次失敗」。
  • 要能打就得在頁面上輸入 token。這個網站是公開的筆記站，鼓勵把正式環境的 token 貼進陌生頁面不是好習慣。
  • 主要讀者是一年後回來查參數的作者，他要的是「參數叫什麼、回什麼」，送請求在終端機用 cURL 更可靠，也不受 CORS 限制。
  • 如果之後要做，前提是 spec 的 server 明確允許跨域，並在 plugin options 加 tryIt: true 讓作者自己打開。
