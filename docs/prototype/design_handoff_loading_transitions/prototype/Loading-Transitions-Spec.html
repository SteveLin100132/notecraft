NOTECRAFT 工作台 ・ 功能設計

Loading 與轉場

工作台是 Astro 靜態 MPA，每次切換筆記都是整頁導覽。這份規格處理兩個空白瞬間：第一次進站時殼還沒畫出來，以及換頁時主區先空一下。原則是殼（Rail、Sidebar、頁籤列）在換頁時完全不動，只有主區做 200–280ms 的淡入；骨架只在等待超過 150ms 時出現，出現後至少停 300ms。

下方畫面是 Loading 與轉場 Prototype 的實際渲染，以 ?loadDemo= 參數凍結在指定狀態。Prototype 右下 Tweaks 的「模擬網路」可切到慢速或卡住，看完整時序；「重播啟動載入」可重看第一次進站。

01時序與門檻

一次換頁分成四段：舊頁等回應、View Transition、主區 Body、互動元件 hydrate。只有超過 150ms 的那段才會讓使用者看到等待狀態。下圖是 Prototype「慢速」與「快」兩種設定的實際時間。

門檻值套用在做法
出現延遲150ms所有骨架、island 佔位、舊頁進度線CSS transition-delay 搭配 @starting-style 從 opacity 0 開始，不需要 JS，串流中的 HTML 也適用。
最短顯示300msJS 控制的替換：island 佔位、Prototype 的 Body 骨架內容在 150ms 內到就直接換，骨架完全不出現；超過 150ms 則等到「出現後滿 300ms」才換，避免閃一下。純 CSS 骨架沒有最短顯示，改靠內容的 200ms 淡入讓替換不生硬。

02啟動 Loading（第一次進站）

不做 splash，也不加額外的品牌元素。Rail 上的標誌與 Sidebar 的「NoteCraft 工作台」本來就是殼的一部分，第一個位元組就帶著真實內容輸出，所以網路快時看到的就是正式畫面。只有資料（樹狀項目、Header、Body）在 150ms 後以骨架呈現，區段標題這類靜態文字直接輸出真值。

骨架換成內容

正式版沒有覆蓋層。每個區域把骨架放在內容之前，CSS 一看到內容的開頭就把骨架藏起來：.nc-body-wrap:has(> .nc-content) > .nc-body-sk{display:none}。HTML 串流到哪裡就換到哪裡，殼與內容各自出現，不會整片閃一下。內容進場用 200ms 淡入（--nc-dur-swap）。Prototype 因為整頁由 React 渲染，用一層同樣排版的覆蓋層 200ms 淡出來模擬。

04視覺化元件佔位與「—」佔位

筆記內嵌的互動元件是 client:visible，會晚一拍出現。現在的問題是先空一塊、再突然撐開。改成 SSR 先輸出外框與預留高度，進入視窗前 200px 開始 hydrate，就緒後內容 200ms 淡入，高度不變。

GeneratedFrame 佔位1280×800
外框、圓角、caption 列高 39px 與真實 Figure 相同；檔名 generated/{id}.tsx 是 SSR 真值。內部是低對比的 shimmer 區塊，800ms 後才出現提示文字。
「—」佔位 ・ 本週更新1280×800
SSR 時不知道「今天」，相對數值先輸出「—」。「—」放在與真值同寬的槽位（tabular-nums），換成數字時只做 200ms 淡入，不改寬度。

預留高度從哪來

  • 能在伺服器端渲染的元件（多數生成元件）：Astro 的 client:visible 本來就會輸出 SSR HTML，只是還不能互動，這時不需要佔位，只把按鈕設為 disabled，hydrate 後加上 data-hydrated。
  • 需要量測容器寬度才能畫的元件（使用 ResizeObserver 的那幾支）：SSR 輸出佔位，高度由生成 skill 在驗證時量測後寫進 MDX：<Comp client:visible={{"{"}rootMargin:"200px"{"}"}} data-h="420" />，佔位用 min-height 套這個值。

哪些值會是「—」

層級位置做法
殼內Sidebar 系列進度（3/5、進度條）、頁籤列、手機頁籤計數放在元素後面的 <script is:inline> 同步讀 localStorage 寫入，且位於 #nc-hd 之前，所以 View Transition 的新頁快照已經是真值。換頁時這些值不會變成「—」再跳回來。

決定

D1標題要不要做共享元素轉場？
建議：不做。來源有頁籤（12.5px）、列表列（13px）、Dashboard 卡片、⌘K 四種，與 20px 標題的比例約 1:1.6，快照放大後文字會糊；頁籤在 Header 上方，標題會往下飛過整個 Header，一天切幾十次會很干擾。實作上還要在換頁前把名稱指派給被點的元素。連續性已經由頁籤指示器提供。Tweaks 的「標題共享元素（評估用）」可以實際試看看。
D2頁籤指示器怎麼移動？
建議：把 2px 藍線從 box-shadow 改成獨立元素 .nt-ind，只有 active 頁籤有，命名 nc-tab-ind，讓瀏覽器在兩頁之間補間位置與寬度。前提是頁籤列在快照前就畫好（見 04 的 inline script），否則新頁快照裡是空的頁籤列。新頁籤插入時頁籤列直接換成新排列，只有藍線在動。
D3從列表進入與筆記之間切換要不要不同？
建議：要，但差異很小（位移 8px／4px、280／240ms）。頂層頁面之間只淡入、不位移，因為它們是平行的頁面。type 由來源與目的網址決定，在新頁的 pagereveal 寫進 <html data-nc-vt>。
D4Dashboard、/notes、/plugins、/settings 之間套同一組嗎？
建議：同一組機制，type 用 section。Rail 的選中狀態直接切換、不做動畫。重新整理（navigationType === "reload"）時跳過轉場。
D5回應很慢時，舊頁要不要有反饋？
建議：要。點擊後舊頁還活著，150ms 後在主區頂端出現 2px 進度線（--wb-progress），2.4s 內緩慢長到 85%。舊內容不變暗，避免使用者以為已經換頁。

出現延遲與最短顯示在減少動態下照樣保留，它們是為了避免閃爍，不是動畫。Prototype 的 Tweaks「模擬減少動態」套用同一組規則。
